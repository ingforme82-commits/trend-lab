# 지수 흐름과 분할·비중 판단을 위한 데이터 경로

운영자 방향(2026-11-16): 속보 자체보다 추세에 맞춘 분할과 비중 조절이 핵심. 지수 추세, 현재 비중, 다음 분할 계획, 실행·비용 후 결과를 분리한다. 뉴스 하나로 주문 규칙을 변경하지 않는다.

## 이번 변경
- KIS 체결 전달은 기존 2초 확인을 유지. 중복 요청·숨긴 탭 요청을 막고, 종목별 서버 수신 시각이 15초 넘으면 실시간 표시를 해제한다. 서버 수신 시각은 거래소 체결 시각이 아니므로 종단 지연으로 부르지 않는다.
- Oracle가 검증 후 GitHub에 게시 성공한 공개 snapshot만 /news에 제공. 10초 확인, 본문이 같으면 빈 응답으로 전송량을 줄인다. GitHub CDN 캐시를 우회하지만 원래 뉴스 수집 주기가 10초가 되는 것은 아니다.
- 미게시 후보, 실패·shadow 실행, 검증 문제, 상태/후보 파일 갱신 경쟁, 코드 버전 불일치는 공개하지 않는다. 실패 때 기존 GitHub 경로를 유지한다.
- 흐름 화면은 당일 변화와 일봉 추세를 구분한다. 일봉의 5·10일선과 유지 여부를 확인하기 전 추세 확정으로 표시하지 않는다. 정규 지수와 24시간 프록시를 구분하고, 겹친 뉴스는 원인 확정이 아니다.
- 개인 계좌 비중·금액·주문은 공개하지 않는다. 새 주문 조건·비중 상한·목표 비중·손절 규칙을 임의 설정하지 않는다.

## 다음 연결에서 필요한 근거
1. 규칙 버전과 같은 시점의 정규장 일봉·이동평균·수급.
2. 대사를 마친 평가금액·현금·미체결을 반영한 현재 비중. 보유 수량만으로 비중을 추정하지 않는다.
3. 기존 분할 단위, 누적 비중, 이미 실행한 주문, 남은 승인 조건.
4. 판단 시각의 입력을 보존해 미래 정보 없이 비교하고, 비용 후 손익·낙폭·규칙 준수를 함께 검증.

현재 시세·뉴스의 초단위 수신 표시가 매매 수익이나 PC 독립 주문을 보장하지 않는다. 기존 NH 모의 이전과 체결·재시작 검증은 별도다.
